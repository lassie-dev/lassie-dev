### What I actually do

Most of my work falls into four buckets. I don't try to be everything.

**Stores that sell.** Shopify, WooCommerce and PrestaShop builds where the catalog is structured properly, the checkout is tested with a real transaction before launch, and the client can run the whole thing without calling a developer for every price change.

**Measurement that reconciles.** GA4, Google Tag Manager, Google Ads and Meta CAPI. If your store's revenue doesn't match what Analytics reports, the cause is almost always the data layer, a missing transaction ID, or a payment gateway breaking session attribution. I find it, prove it, then fix it.

**Android that survives the background.** Kotlin, foreground services, AccessibilityService, on-device audio and speech pipelines. Battery profiling is part of the job, not an afterthought, and I test on the manufacturers that kill background services silently.

**Systems that stay up.** C#/.NET workers on Linux VPS, systemd, Docker, log rotation, watchdogs, and monitoring that alerts on data freshness instead of "is the process alive". A hung service that reports healthy is worse than one that crashes.

### How I work

Diagnose before touching. On a broken production system the first move is to preserve the evidence, not to restart the service. Restarting destroys the state that explains the failure, and the same outage comes back a week later.

Prove it, then fix it. No change goes in before the root cause is demonstrated and written down in plain language.

Test the failure on purpose. If I claim something runs 24/7, I've killed the process, rebooted the box and cut the upstream to watch it recover.

Hand over the keys. Every project ships with a written guide and a recorded walkthrough, so the client isn't dependent on me for routine changes.
